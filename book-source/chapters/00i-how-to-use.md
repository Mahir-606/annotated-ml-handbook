## How to read an annotated code block

Every code example is laid out as a two-column table: **the code on the left, a plain-English explanation of that exact line on the right.** On a phone the explanation sits directly under its line. Below the code you will find the **real output** the code produced when this book was built, and any **figure** it drew.

```py title="A first annotated example"
message = "Hello, ML"          #> Create a variable called `message` and store a piece of text (a *string*) in it.
length = len(message)          #> `len()` counts the characters in the string: 9 here, because spaces and commas count.
print(message, "has", length, "characters")  #> `print()` writes values to the screen, separated by spaces.
```

:::note Every output in this book is real
The book was generated by a program that **executed every code block** in order, captured exactly what Python printed, and embedded it. If a block is meant to fail, to teach you an error, its output panel is red and labelled *Error (this is expected)*. If you type the code exactly and get a different result, the difference is a clue: check your library versions (listed on the cover) and look for a typo.
:::

## Setting up your machine {B}

You need Python 3.10 or newer and a handful of libraries. There are two common routes. Pick one.

### Route A: plain Python with a virtual environment

A **virtual environment** is a private folder of libraries for one project, so projects cannot break each other.

```bash title="Create a project and install the libraries"
mkdir ml-project && cd ml-project      #> Make a new folder for the project and move into it.
python -m venv .venv                   #> Create a virtual environment in a hidden folder called `.venv`.
source .venv/bin/activate              #> Activate it (macOS/Linux). Your prompt now starts with `(.venv)`.
# .venv\Scripts\activate               #> The Windows equivalent of the line above (in PowerShell or cmd).
pip install numpy pandas matplotlib seaborn scikit-learn  #> Install the scientific stack into the environment.
pip install tensorflow                 #> Install TensorFlow (large download; only needed for Part VI).
pip install jupyterlab                 #> Optional: an interactive notebook environment in your browser.
pip freeze > requirements.txt          #> Record the exact versions installed, so the project can be recreated later.
```

### Route B: Anaconda / Miniconda

```bash title="The conda equivalent"
conda create -n ml python=3.12         #> Create an environment called `ml` with Python 3.12.
conda activate ml                      #> Switch into it.
conda install numpy pandas matplotlib seaborn scikit-learn jupyterlab  #> Install the stack from conda's channel.
pip install tensorflow                 #> TensorFlow is usually installed with pip, even inside conda.
```

### Check that everything works

```py title="Verify your installation"
import sys                             #> `sys` gives access to information about the running Python interpreter.
import numpy as np                     #> Import NumPy under its standard nickname `np`.
import pandas as pd                    #> Import pandas as `pd`, the universal convention.
import sklearn                         #> scikit-learn's import name is `sklearn`, not `scikit-learn`.
print("Python ", sys.version.split()[0])  #> `sys.version` is a long string; `split()[0]` keeps just the number.
print("NumPy  ", np.__version__)       #> Every major library stores its version in `__version__`.
print("pandas ", pd.__version__)  #> pandas' version (this book uses 3.x).
print("sklearn", sklearn.__version__)  #> scikit-learn's version.
```

:::bug `ModuleNotFoundError: No module named 'sklearn'`
You installed the library into a different Python than the one running your code. Activate the right environment, or run `python -m pip install scikit-learn` using the *same* `python` that runs your script. In Jupyter, run `%pip install scikit-learn` inside a cell.
:::

## Where to write code

- **Jupyter notebooks** (`jupyter lab`): run code cell by cell and see outputs and plots inline. Ideal for exploration and learning.
- **Scripts** (`.py` files run with `python my_script.py`): ideal for anything you will re-run, share or put in a paper's code repository.
- **An editor** such as VS Code or PyCharm gives you autocomplete, a debugger and notebook support in one place.

:::research Notebooks for exploring, scripts for results
A common research workflow: explore in a notebook, then move the final, cleaned-up analysis into scripts or functions that run top-to-bottom without manual steps. A result you can regenerate with one command is a result you can defend.
:::
