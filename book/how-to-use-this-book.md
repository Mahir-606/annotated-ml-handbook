# How to use this book

This handbook takes you from your first line of Python to running, validating and reporting machine-learning analyses in real research. It is built to be read in order by beginners, dipped into by intermediate learners, and searched by anyone who is stuck on an error at 2 a.m.

## The map of the book

The book is a route with eight stations. Each Part has its own colour, used on its opening page, its section numbers and its boxes, so you always know where you are.

## Three ways to read it

| You are… | Start here | Then |
|---|---|---|
| **New to programming** | Part I, [Chapter 1](../notebooks/part-1-python/01-python-basics.ipynb), in order | Do every "Try it yourself" box before moving on. Parts II–IV come next. |
| **Comfortable with Python, new to ML** | Skim Part I, then Parts II–IV | Part V (scikit-learn) and Part VII (the research protocol) are your core. |
| **Already doing ML** | Part VII and the Debugging part | Use the search box (top right) and the Appendix quick-reference sheets as a desk reference. |

Every section heading carries a level tag: *Beginner* *Intermediate* *Advanced*. You can skip Advanced sections the first time through and come back later.

## How to read an annotated code block

## Setting up your machine · *Beginner*

You need Python 3.10 or newer and a handful of libraries. There are two common routes. Pick one.

### Route A: plain Python with a virtual environment

A **virtual environment** is a private folder of libraries for one project, so projects cannot break each other.

**Create a project and install the libraries**

```bash
mkdir ml-project && cd ml-project
python -m venv .venv
source .venv/bin/activate
# .venv\Scripts\activate
pip install numpy pandas matplotlib seaborn scikit-learn
pip install tensorflow
pip install jupyterlab
pip freeze > requirements.txt
```

<table>
<tr><td><code>mkdir ml-project &amp;&amp; cd ml-project</code></td><td>Make a new folder for the project and move into it.</td></tr>
<tr><td><code>python -m venv .venv</code></td><td>Create a virtual environment in a hidden folder called <code>.venv</code>.</td></tr>
<tr><td><code>source .venv/bin/activate</code></td><td>Activate it (macOS/Linux). Your prompt now starts with <code>(.venv)</code>.</td></tr>

### Check that everything works

**Verify your installation**

```python
import sys
import numpy as np
import pandas as pd
import sklearn
print("Python ", sys.version.split()[0])
print("NumPy  ", np.__version__)
print("pandas ", pd.__version__)
print("sklearn", sklearn.__version__)
```

<details open><summary><b>What each line does</b></summary>

<table>
<tr><td><code>import sys</code></td><td><code>sys</code> gives access to information about the running Python interpreter.</td></tr>
<tr><td><code>import numpy as np</code></td><td>Import NumPy under its standard nickname <code>np</code>.</td></tr>
<tr><td><code>import pandas as pd</code></td><td>Import pandas as <code>pd</code>, the universal convention.</td></tr>
<tr><td><code>import sklearn</code></td><td>scikit-learn&#x27;s import name is <code>sklearn</code>, not <code>scikit-learn</code>.</td></tr>
<tr><td><code>print(&quot;Python &quot;, sys.version.split()[0])</code></td><td><code>sys.version</code> is a long string; <code>split()[0]</code> keeps just the number.</td></tr>
<tr><td><code>print(&quot;NumPy  &quot;, np.__version__)</code></td><td>Every major library stores its version in <code>__version__</code>.</td></tr>
<tr><td><code>print(&quot;pandas &quot;, pd.__version__)</code></td><td>pandas&#x27; version (this book uses 3.x).</td></tr>
<tr><td><code>print(&quot;sklearn&quot;, sklearn.__version__)</code></td><td>scikit-learn&#x27;s version.</td></tr>
</table>
</details>

> **🐞 Bug hunt** · **`ModuleNotFoundError: No module named 'sklearn'`**
>
> You installed the library into a different Python than the one running your code. Activate the right environment, or run `python -m pip install scikit-learn` using the *same* `python` that runs your script. In Jupyter, run `%pip install scikit-learn` inside a cell.

## Where to write code

- **Jupyter notebooks** (`jupyter lab`): run code cell by cell and see outputs and plots inline. Ideal for exploration and learning.
- **Scripts** (`.py` files run with `python my_script.py`): ideal for anything you will re-run, share or put in a paper's code repository.
- **An editor** such as VS Code or PyCharm gives you autocomplete, a debugger and notebook support in one place.

> **🔬 Research practice** · **Notebooks for exploring, scripts for results**
>
> A common research workflow: explore in a notebook, then move the final, cleaned-up analysis into scripts or functions that run top-to-bottom without manual steps. A result you can regenerate with one command is a result you can defend.
